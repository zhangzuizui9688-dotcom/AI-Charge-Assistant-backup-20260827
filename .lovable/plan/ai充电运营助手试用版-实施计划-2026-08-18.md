# AI充电运营助手试用版 — 实施计划

纯前端交互原型：不接数据库、不登录、不启用 Cloud、不调用外部 API 或 AI。全部为模拟数据 + 本地状态，界面与文案全中文。

实施前先检查项目实际目录结构与入口文件，在现有项目结构与技术栈中开发，不更换路由方案，不预设具体入口文件路径。页面标题与描述按现有技术栈已有的实现方式添加。只运行项目已有的类型检查、构建与代码检查命令。

## 1. 页面结构

单页面（应用现有入口页面），三层结构：

```text
+--------------------------------------------------------------+
| 顶栏  AI充电运营助手试用版 | 角色下拉(老板/车管/安全) | 演示提示 |
+--------------------------------------------------------------+
| 演示横幅：当前为演示数据，不代表真实运营结果                    |
+---------------+----------------------------------------------+
| 左侧导航(静态) | 主内容：模拟充电运营平台工作台（固定内容）     |
| 运营总览      |  - KPI 卡片行（演示汇总）                      |
| 站点管理      |  - 天气预警条（A站橙 / B站黄 / C站正常）        |
| 车辆管理      |  - 站点状态表格                                |
| 报障工单      |  - 近期报障列表                                |
| 报表中心      |                                              |
+---------------+----------------------------------------------+
                                     右下角悬浮按钮「AI充电运营助手」
                                     点击 → 右侧展开 Chatbot（宽约 420px）
```

- 左侧导航仅为静态视觉背景，不实现点击高亮或跳转逻辑。
- 主工作台内容固定，不随角色重构 KPI。
- 角色切换只影响：Chatbot 欢迎语、快捷问题、可查询内容范围、对话记录。
- 演示提示同时出现在页面横幅与 Chatbot 头部。

## 2. 组件清单

不安装 AI Elements 或其他额外 Chatbot 依赖。优先复用项目已具备的 shadcn 组件；缺失时只补装实际需要的最少组件（Card、Button、Sheet、ScrollArea、Input、Select、Badge、Table、Dialog、Separator）。不生成专属助手图片或标识图，入口图标使用现有 lucide-react 图标（Bot 或 MessageCircle）。

平台外壳

- `AppHeader`：标题、角色下拉、演示标识
- `DemoBanner`：演示数据提示
- `SideNav`：静态导航
- `Dashboard`：工作台容器
- `KpiCard`、`WeatherAlertBar`、`StationTable`、`FaultList`

Chatbot（基于 Sheet + ScrollArea + Card + Input + Button 自建，无额外依赖）

- `AssistantLauncher`：右下角悬浮入口（Bot 图标）
- `AssistantPanel`：右侧面板（头部含角色名、演示提示、清空当前角色对话）
- `MessageList` / `MessageBubble`：用户消息为 primary 填充气泡，助手消息无底色
- `QuickQuestions`：角色快捷问题按钮组
- `Composer`：输入框 + 发送按钮
- `ThinkingIndicator`：文字型「思考中…」加载状态，无复杂动画

消息内富卡片

- `RiskCard`、`RuleCard`、`DataTable`、`TimelineCard`、`ReportCard`
- `BriefingCard`、`OffPeakOptimizationCard`
- `FaultDetailCard`、`StatusTag`、`ActionButtons`

## 4. 三种角色的快捷问题

老板

1. 昨日经营情况怎么样？
2. 毛利率为什么变化？
3. 有哪些车在非谷平期充电？
4. 优化后预计能省多少钱？

车管人员

1. 今日新增了哪些车辆报障？
2. 哪些故障会影响出车？
3. 有哪些超时未处理的报障？
4. 有重复故障的车辆吗？

安全负责人

1. 当前有哪些恶劣天气预警？
2. 受影响的站点和在充车辆有多少？
3. 这个风险等级的判断依据是什么？
4. 生成一份安全事件报告。

安全负责人欢迎语（固定文案）：
"您好，我是AI充电运营助手。当前A站存在1条雷暴橙色预警，有18辆车正在充电。您可以查看风险依据、在充车辆或发起演示停桩审批。当前全部为模拟数据。"

## 5. 主要对话流程

意图匹配顺序：**先按当前角色限制可调用意图范围，再做关键词打分匹配**。

角色可访问意图：

- 老板：经营简报、收入/成本/毛利、非谷平期充电、待优化车辆、预计节省费用。
- 车管人员：车辆报障、影响出车故障、司机反馈、超时故障、重复故障、单辆车详情、模拟更新报障状态。
- 安全负责人：天气预警、风险依据、受影响站点、正在充电车辆和设备、模拟通知记录、模拟停桩审批、事件时间线、安全事件报告。

越权提问回复："当前【角色名称】演示视角不提供该类信息，请切换到对应角色后查询。"
角色范围内但无法识别时，回复无法识别提示并列出当前角色的可提问范围。

安全卫士主线

1. 问天气 → `RiskCard`（A站雷暴橙色 / B站暴雨黄色 / C站正常，含来源与更新时间、在充车辆与设备数）+ 操作按钮：查看风险依据 / 查看正在充电的车辆 / 通知现场负责人 / 发起停桩审批 / 查看事件时间线 / 生成安全事件报告
2. 查看风险依据 → `RuleCard`（触发规则与判定条件）
3. 查看在充车辆 → `DataTable`（车牌、站点、SOC、开始时间、预计完成）
4. 通知现场负责人 → 回复："模拟通知记录已创建。本操作未向任何真实人员发送消息。"；时间线追加："当前用户创建了一条模拟现场通知记录，未触达真实人员。"
5. 发起停桩审批 → 先弹出二次确认框，显示：站点 A站 / 涉及设备 16台 / 当前正在充电车辆 18辆 / 操作性质：仅创建模拟审批记录 / 不会连接或控制任何真实设备；按钮为「确认创建模拟审批」与「取消」。确认后回复："模拟停桩审批已创建，编号DEMO-AP-001，状态为待审批。本操作未连接或控制真实充电设备。"
6. 查看事件时间线 → `TimelineCard`
7. 生成安全事件报告 → `ReportCard`（前端文本生成 + 复制，不生成 PDF），底部固定显示："本报告使用模拟数据，用于展示系统预警、通知和处置记录能力，不代表真实事件，不直接替代专业事故调查或法律责任认定。"

表述统一规则：所有模拟操作回执必须区分「模拟记录已创建 / 真实消息未发送 / 真实人员未触达 / 真实设备未控制」，禁止出现"已通知""已送达""已停止设备"等可能被理解为真实操作的表述。

老板主线：昨日简报 `BriefingCard`（收入/成本/毛利/毛利率/较近 7 日均值变化/变化原因，固定显示成本统计范围说明，预计节省与已实现节省分列）→ 非谷平期充电优化 `OffPeakChargingOptimizationCard`（待优化车辆 23 辆、可转移电量 2,180 度、预计增加电费 1,460 元、预计可节省费用、已实现节省 0 元）→ 查看待优化车辆 `DataTable`。禁止把预计节省描述为已取得收益。

车管主线：今日新增报障（演示汇总 + 5 条详情）→ 影响出车 / 超时未处理 / 重复故障筛选 → 单车 `FaultDetailCard`（分类、严重度、司机最新反馈、处理历史）→ 模拟更新处理状态（本地更新 + "模拟执行结果"回执）。每条故障详情固定显示："以上为基于当前演示数据的初步判断，不能替代车辆检修结论。"，不直接确定责任方。

## 6. 状态管理方式

- React Context + `useReducer`，状态：`role`、`isOpen`、`messagesByRole`、`isThinking`、`demoOverridesByRole`。
- 三个角色各自保存独立的对话历史与演示操作记录（审批、模拟通知、报障状态变更、时间线追加）。
- 切换角色后加载该角色的历史对话，不显示其他角色的业务对话，可插入系统提示："当前已切换至【安全负责人】演示视角。"
- 清空对话仅清空当前角色的对话与该角色产生的演示操作，其他角色不受影响。
- 持久化：`localStorage` 单键存储 `role / messagesByRole / demoOverridesByRole`，在客户端副作用中读取以避免水合不匹配。
- 模拟加载：发送后 `isThinking = true`，短暂延时后插入助手消息。
- 无全局状态库、无网络请求。

## 7. 一次性实施步骤

1. 检查项目现有目录结构、入口页面、已安装的 shadcn 组件与可用脚本命令。
2. 在现有样式系统中补充设计令牌：深蓝主色、白底、中性灰，新增四级风险色（绿/黄/橙/红）；不加渐变与大动画。
3. 只补装缺失且必需的 shadcn 组件。
4. 新建模拟数据文件：weather/stations、vehicles、briefing、offPeakOptimization、faults、roles（欢迎语 + 快捷问题 + 可访问意图）。
5. 新建意图模块：先做角色范围过滤，再做关键词匹配；意图 → 消息负载映射。
6. 新建 Assistant Context（reducer + 按角色分区的 localStorage 持久化）。
7. 实现平台外壳与固定工作台组件。
8. 实现 Chatbot 面板与全部富卡片、停桩审批二次确认框，操作动作走 reducer。
9. 在现有入口页面组装整页，并按现有技术栈方式设置中文页面标题与描述。
10. 自检：桌面 1440 / 1280 布局、窄屏基本可用、文案合规，运行项目已有的类型检查、构建与代码检查命令。
